# 商品兑换

本文说明商品兑换接口、开放窗口、二次确认以及成功或失败后的页面状态更新。

## 相关文件

```text
src/views/ShopView.vue
src/components/ShopPage.vue

```

---

## `POST /shop/consume` 兑换商品

### 接口定义

```http
POST /shop/consume
```

### 请求参数

| 参数         | 说明    |
| ------------ | ------- |
| `product_id` | 奖品 ID |

### 成功响应

推荐响应如下：

```json
{
  "points_after": 70,
  "created_at": "2026-07-20T13:00:00"
}
```

### 字段映射

| 后端字段       | 前端字段      | 说明             |
| -------------- | ------------- | ---------------- |
| `points_after` | `pointsAfter` | 兑换后的积分余额 |
| `created_at`   | `createdAt`   | 兑换发生时间     |

### 异常处理

兑换窗口不合法、积分不足、商品不可兑换或请求失败时，后端返回非 `2xx` 和明确的 `message`。前端不扣减本地积分，按钮短暂展示“兑换失败”。

## 页面更新

- 构建期配置 `VUE_APP_SHOP_REDEEM_ALWAYS_OPEN` 默认关闭，仅字符串 `true`（忽略首尾空格和大小写）开启；`false`、未配置及其他值均保持原有规则。
- 开关开启时，从商城首屏到二次确认提交前都无条件开放前端兑换窗口，展示“兑换已开放”，不依赖当前赛季接口，不受无激活赛季、赛季日期、配置保护期或赛季查询失败影响，也不改写其他页面共用的赛季状态。
- 开关关闭时，商城仅在当前赛季开始日起的前 N 个自然日允许兑换，`N` 由构建期环境变量 `VUE_APP_SHOP_REDEEM_WINDOW_DAYS` 配置；未配置、非正整数或不存在时默认 `7`。
- 开关关闭时，即使处于商城兑换窗口，当前赛季的配置保护期内仍禁止兑换。页面展示“兑换将在 N 小时后开放”并禁用全部兑换按钮，商品和积分流水继续可见；商城不复用项目首页的“赛季正式开始”文案。
- 普通模式同时监听兑换窗口和配置保护期的最近边界；停留跨过边界时自动刷新按钮状态，二次确认提交前也会再次计算。强制开放模式不创建窗口定时器，并清理已有定时器。
- 前端通过 `GET /season/current` 的 `start_date`、`end_date` 计算窗口：`start_date` 当日为第 1 天，窗口结束日零点起不再允许兑换；窗口天数超过赛季天数时，最多开放至赛季结束日。
- 普通模式中，兑换窗口未开放、已结束或当前赛季加载失败时，页面展示原因并禁用全部兑换按钮；二次确认提交前会再次计算，防止页面停留期间跨过窗口仍发起请求。
- 开关只控制前端交互，仍保留积分不足、提交中禁用和二次确认；后端 `POST /shop/consume` 独立执行登录鉴权、商品可见性、积分余额和配置保护期校验，后端拒绝时仍显示兑换失败，不扣减本地积分。当前后端没有前 N 天的兑换窗口校验，也不读取此前端开关；没有激活赛季时不会因赛季缺失拒绝兑换，因此开启开关后仍可正常兑换。
- 用户点击“兑换”后先进入“确认兑换”，再次点击才提交兑换。
- 提交后按钮进入“兑换中”状态，并显示加载动画。
- 前端会在进入“兑换中”后延迟 1 秒再调用接口，让中间态动画有可感知的停留。
- 调用 `POST /shop/consume` 时，请求体传入 `product_id`。
- “兑换中”会保留最短展示时长，避免接口过快返回导致状态切换突兀。
- 兑换成功后使用 `points_after` 更新可用积分。
- 兑换成功后用 `created_at` 生成一条本地即时兑换流水，并与已有积分流水按时间倒序展示。
- 兑换失败时不扣减积分，按钮短暂展示“兑换失败”。
- 普通模式中，当前没有激活赛季时，商品与积分流水仍可浏览，但顶部明确显示“当前暂无激活赛季，兑换敬请期待”，全部兑换按钮显示“敬请期待”并保持禁用。

## 配置生效与验证

在客户端环境文件中配置，或在部署目录 `.env` 中由 Compose 传入构建参数：

```dotenv
VUE_APP_SHOP_REDEEM_ALWAYS_OPEN=true
```

修改后重启开发服务，生产环境重新构建前端；仅重启静态资源容器不会更新编译后的配置。独立镜像构建使用 `--build-arg VUE_APP_SHOP_REDEEM_ALWAYS_OPEN=true`。

验证开关开启时的无赛季、日期无效、赛季开始前、窗口结束后与配置保护期场景，均应展示可兑换时间状态；积分不足仍禁用，积分足够仍需二次确认。关闭或配置无效时，应恢复原有窗口和保护期限制。服务端拒绝或网络失败时应保留原余额。
