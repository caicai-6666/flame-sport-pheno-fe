# UploadProofPanel 记录上传

本文说明运动凭证上传配置、表单规则、图片处理、提交反馈和即时历史更新方式。

## 组件位置

```text
src/components/UploadProofPanel.vue
src/components/ProjectHome.vue
src/views/ProjectHomeView.vue
src/api/projects.js
src/utils/proofImageProcessing.js
```

## 当前真实数据范围

已接入：

- `GET /proof/config`
- `POST /proof/upload`

无激活赛季时，首页不会打开上传弹窗；即使通过旧页面缓存或异常入口绕过前端，后端也必须拒绝没有有效当前赛季的 `POST /proof/upload`。

上传成功后，前端会即时追加一条记录到 `appState.uploadRecords`，因此当前会话中进入 `HistoryPage` 能立即看到新上传内容。即时记录会仅在内存中保留本次提交的 WebP Blob；后端尚未返回 `imageUrl` 时可直接查看这张临时原图。
进入 `HistoryPage` 时，前端会重新查询当前赛季上传历史；即时追加只用于上传成功后的当前会话反馈。

用户完成图片处理后，可点击上传摘要中的“查看处理后的图片”翻转上传面板至背面，在独立的可滚动区域查看完整 WebP 长图；点击“返回编辑”翻回表单，上传字段和已选图片保持不变。

图片压缩、WebP 兼容编码和多图纵向拼接已经集中在 `src/utils/proofImageProcessing.js`。普通上传面板与历史页补传卡共同调用该模块，确保图片数量、清晰度、文件大小和钉钉兼容策略一致。

## `GET /proof/config` 获取项目上传配置

### 接口定义

```http
GET /proof/config?project_id=1
```

### 请求参数

| 参数名       | 类型              | 是否必填 | 说明    |
| ------------ | ----------------- | -------: | ------- |
| `project_id` | `string / number` |       是 | 项目 ID |

### 成功响应

推荐响应如下：

```json
[
  {
    "id": "10",
    "record_type": "普通记录",
    "upload_hint": "步数截图、手环记录或健康 App 截图",
    "note_example": "例如：今日累计 8600 步"
  }
]
```

兼容包装：

```json
{
  "uploadConfigs": []
}
```

前端处理：

- `id` 归一化为 `uploadConfigId`
- `record_type` 归一化为 `recordType`
- 类型名称去除首尾空格；旧编码 `month-start`、`month-end` 分别兼容为“月初记录”“月末记录”，与历史接口使用同一 API 归一化函数
- 只有一条配置时不展示记录类型切换器
- 多条配置时展示切换按钮
- 缺少 `id` 时不允许提交
- 上传配置按 `project_id` 缓存在前端，同一项目重复打开上传弹窗时不重复请求

### 异常处理

配置请求失败或返回记录缺少 `id` 时，上传面板阻止提交并保留重试入口，不使用模拟配置。

## `POST /proof/upload` 上传运动凭证

当前赛季处于配置保护期时，项目首页不会打开上传面板。若保护期在面板打开期间开始，前端会立即收起面板；面板自身也会禁用文件、记录类型、运动日期、备注和提交操作，防止状态切换竞态继续发起写请求。

用户可见文案统一表达为“赛季尚未正式开始”或“即将开始”，不展示内部配置保护期概念。

### 接口定义

```http
POST /proof/upload
```

### 请求参数

请求体使用 `FormData`：

| 字段名                     | 类型              | 是否必填 | 说明                                      |
| -------------------------- | ----------------- | -------: | ----------------------------------------- |
| `season_id`                | `string / number` |       是 | 当前赛季 ID                               |
| `project_id`               | `string / number` |       是 | 项目 ID                                   |
| `project_upload_config_id` | `string / number` |       是 | 上传配置 ID                               |
| `proof_date`               | `string`          |       是 | 凭证对应的实际运动日期，格式 `YYYY-MM-DD` |
| `note`                     | `string`          |       是 | 用户备注                                  |
| `image`                    | `File`            |       是 | 前端处理后的 WebP 图片                    |
| `image_segments`           | `string`          |       否 | 图片分段定位 JSON；当前前端单图、多图均提交 |

示例：

```text
season_id=2026-07
project_id=1
project_upload_config_id=10
proof_date=2026-07-19
note=今日累计 8600 步
image=steps-20260719.webp
```

### 图片分段定位

图片处理工具返回 `{ blob, imageSegments }`，组件在同一次图片选择完成后保存二者，并由 `src/api/projects.js` 将 `imageSegments` 序列化为 multipart 文本字段 `image_segments`。示例：

```json
{
  "version": 1,
  "width": 1440,
  "height": 6000,
  "segments": [
    { "x": 16, "y": 16, "width": 1408, "height": 2800 },
    { "x": 16, "y": 2832, "width": 1408, "height": 3152 }
  ]
}
```

- 坐标以最终 WebP 左上角为原点，单位为像素；画布尺寸必须与上传文件一致。
- 单图提交覆盖最终压缩图片的一个矩形；多图按选择顺序提交各原图实际绘制的矩形，排除白色边距和图片间隙。
- 每次缩宽重绘时重新计算坐标，只提交最终成功编码对应的定位；坐标不使用预览区域或原始文件尺寸。
- `version` 固定为整数 `1`；对象只包含 `version`、`width`、`height`、`segments`，矩形只包含 `x`、`y`、`width`、`height`。
- 分段数量为 1 ～ 5，坐标为非负整数，宽高为正整数；矩形不能越界，必须从上到下排列且纵向不能重叠。JSON 的 UTF-8 大小不能超过 4096 字节。
- 重新选图、处理失败或重置表单时同步清空定位；已有异步选择标识同时保护图片和定位，防止较早的处理结果覆盖新选择。

后端允许旧客户端省略或留空该字段，此时清空旧定位；JSON 文本 `null` 不合法。当前前端要求图片与定位均处理完成才允许提交。同日期重传会整体替换图片与定位，成功响应结构保持不变。

### 成功响应

推荐响应如下：

```json
{
  "created_at": "2026-07-19T13:20:00+08:00",
  "proof_date": "2026-07-19"
}
```

### 异常处理

分段定位 JSON 非法、尺寸不符、坐标越界等校验失败时返回 `400`，后端不落盘、不更新凭证；页面沿用上传失败按钮反馈，保留图片、定位和表单供重试。

日期、备注、文件格式、赛季状态或配置保护期不合法时，后端必须拒绝请求并返回明确的 `message` 或 `detail`。写操作不自动重试；失败时前端保留表单内容并恢复可提交状态。

## 备注填写引导

上传面板使用单列玻璃质感日期滚轮，不提供月份切换：中央单行高亮展示当前选择，左侧三角标指向选中行，上下仅淡化露出相邻日期。滚轮仅列出本月中位于赛季起止范围内、且不晚于今天的日期，默认选择当天（今天不在有效范围时才回退到最后一个有效日）。因此不能上传未来日期或上月记录。前端限制之外，后端仍会再次校验日期范围，防止构造请求绕过限制。

当前选中记录类型为“月初记录”或“月末记录”时，不展示日期滚轮，`proof_date` 固定为当天，与项目名称无关；当天不在有效日期范围时禁止提交，不回退到其他日期。其他记录类型展示日期滚轮，即使项目名称为“减重挑战”也遵循该规则。提交请求仍照常携带 `proof_date` 必填字段。

上传配置异步加载完成，以及在月初/月末类型与普通类型之间切换时，重新应用日期默认值并取消待执行的滚轮同步和提交二次确认，避免隐藏日期控件后仍提交之前选中的日期。切回普通类型后恢复日期滚轮，并定位默认日期。上传请求进行中禁止切换类型，避免即时历史类型与已提交配置不一致。

同一项目同一运动日期只能保留一条有效记录。用户再次提交相同日期时，后端按重传处理并重新初审；前端即时历史也会替换该日期的旧记录。

备注为必填项。前端拒绝空白备注，输入框下方会提示用户填写时长、距离、次数、步数等可核验指标；描述越具体，越便于初审核验并有助于通过初审。

## 移动端弹窗布局与兼容

- `UploadProofPanel` 通过 `Teleport` 挂载到 `body` 的全局模态层，不受路由页面和滑动过渡形成的层叠上下文限制；遮罩完整覆盖 Header，Header 不会压住上传面板或在弹窗打开时继续接收操作。
- 面板顶部使用 `--header-height + safe-area-inset-top + edge-gap` 计算，始终位于 Header 真实底边之后；底部依据导航高度和 `safe-area-inset-bottom` 避让悬浮底栏。常规屏幕边距为 `16px`，高度不超过 `640px` 时收紧为 `10px`。
- 上传表单的图片、配置和备注区域可在弹窗内部滚动；提交按钮固定在弹窗底部、横向填满操作区并保留圆角内边距，避免小屏幕或钉钉内置浏览器可视高度变化时被内容挤出。
- 备注输入框使用至少 `16px` 的字号，避免 iOS Safari 和部分移动 WebView 在输入框聚焦时自动放大页面；不通过禁止页面缩放的 viewport 配置规避该行为。
- 上传图片框线和主要颜色先使用基础 CSS 颜色作为回退，再叠加 `color-mix()` 的增强效果；不支持该函数的旧版 Android WebView 仍会显示绿色虚线边框和可辨识的上传区域。

## 图片处理

用户每次可选择 1 ～ 5 张图片：

- 钉钉/移动端拍照入口每次只能产生 1 张新照片；从相册或文件选择图片时最多可同时选择 5 张。
- 选择 1 张时，沿用单图处理流程。
- 选择 2 ～ 5 张时，前端按选择顺序纵向拼接为一张白底 WebP 长图；每张图片只做等比缩放，完整保留、不裁切、不拉伸。长图优先保留约 960 px 以上的可读宽度，不会仅为压缩体积继续缩小到文字难以辨识；在此清晰度下仍超出 5 MB 时提示用户减少图片数量或选择更清晰的截图。
- 最终仍只向后端提交一个 `image` 文件，不增加接口字段或改变审核、历史记录逻辑。
- 超过 5 张或包含非图片文件时，前端会拒绝本次选择并提示用户重新选择。

无论单图或多图，前端都会：

1. 读取任意 `image/*` 图片
2. 绘制到 `canvas`
3. 透明区域先铺白底
4. 优先通过 Canvas 原生编码导出 `image/webp`
5. 同时校验 Blob MIME 和 `RIFF...WEBP` 文件头；原生编码不受支持或悄然回退为 PNG 时，按需加载 `@jsquash/webp` 的 libwebp WebAssembly 编码器重新生成 WebP
6. 单图从长边 1920 px 开始压缩；多图长图按宽度优先保留清晰度。
7. 逐步降低 WebP 编码质量，必要时仅缩小长图宽度。
8. 确保最终文件小于 5 MB。

WASM 编码器仅在当前 WebView 无法原生编码 WebP 时动态下载和初始化，兼容设备不会承担额外加载成本。编码器提供普通版和 SIMD 版，由运行时自动选择；若钉钉 WebView 连 WebAssembly 也不支持，或编码器资源加载、执行失败，前端会停止提交并提示用户重试或升级钉钉，不会把伪装成 `.webp` 的 PNG 上传给后端。

最终上传文件满足：

```text
Content-Type: image/webp
文件大小 <= 5 MB
文件后缀 = .webp
```

## 文件命名规则

前端不再向用户展示或开放图片重命名。提交文件名由前端内部生成：单图采用原文件主名，多图采用首图主名加“`-N张凭证`”，统一清理不适合文件名的字符并追加 `.webp` 后缀。

## 按钮状态

```text
提交记录 -> 确认提交 -> 上传中 -> 成功关闭面板
```

失败时：

```text
上传中 -> 上传失败 -> 恢复可重试
```

为了避免接口过快返回导致状态闪烁，前端保证“上传中”至少展示约 1.8 秒。该延迟只影响 UI 状态结束，不延迟真实网络请求发起。

## HistoryPage 即时追加

后端返回 `created_at` 和 `proof_date`。上传成功后，前端使用本次提交时已有信息追加本地历史记录：

- `taskName`
- `projectId`
- `fileName`
- `recordType`
- `note`
- `reviewStatus = pending`
- `proofDate = proof_date`
- `uploadedAt = created_at`
- `temporaryImageBlob = 本次提交的 WebP Blob`，仅当前页面会话用于查看刚上传的原图，不持久化；刷新页面或历史接口重新拉取后自动丢弃，改用后端返回的 `imageUrl`

这里的 `recordType` 仅用于前端展示，后端写库依据是 `project_upload_config_id`；`proofDate` 用于在即时历史中替换同项目同日期的旧记录。

即时历史副标题直接使用所选配置的类型名称，例如“月初记录”“月末记录”，不依赖项目名称。历史接口重新加载后使用服务端返回的记录类型；字段缺失时显示“运动上传”，不推断为月初。
